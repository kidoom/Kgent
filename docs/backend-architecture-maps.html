系统架构图

当前网络入口是 FastAPI。HTTP 负责提交命令，SSE 负责推送事件； 运行时状态集中在 RunManager，核心 agent loop 通过 Host 抽象向外发事件。

读代码时可以从 api/sessions.py:send_message() 开始，顺着 schedule_run()、RunManagerHost、run_agent_stream() 走。

模块图

后端模块按职责拆得比较清楚：传输层在 api，运行时在 runtime，模型适配在 model， 工具能力在 tools，短时记忆在 memory。

backend/app single process runtime

api/

HTTP 命令路由与 SSE 事件流。

  • sessions.py 发消息、审批、取消
  • events.py SSE stream
  • runtime_service.py 后台 task

runtime/

Agent loop、事件协议、权限、Host 抽象。

  • loop.py 核心循环
  • run_manager.py run 监督器
  • protocol.py AgentEvent

model/

模型厂商适配层，把 provider 响应归一成 ModelResponse。

  • base.py 协议和注册表
  • openai.py tool_calls 转换

tools/

真实可执行工具和 schema 投影。

  • base.py Tool Protocol
  • registry.py 构建工具列表
  • read_file.py 路径安全

memory/

进程内短时记忆，保存 session 的 messages。

  • session_store.py get / trim / reset

core/

环境变量和 .env 配置解析。

  • config.py Settings
  • provider、model、权限模式

cli/

本地调试入口，复用同一个 loop。

  • debug.py CLIHost
  • 可手动审批工具

tests/

离线 fake model 和后端关键链路测试。

  • fake_model.py provider=fake
  • test_http_runtime.py 集成测试

核心数据结构图

Kgent 的核心不是数据库表，而是一组内存数据结构。理解这些结构，就能理解 agent loop 如何流动。

runtime/messages.py runtime/protocol.py runtime/run_manager.py

Message

  • role system | user | assistant
  • content str | blocks[]
  • assistant_text str | null

ToolUseBlock

  • type tool_use
  • id call id
  • name tool name
  • input dict

ToolResultBlock

  • type tool_result
  • tool_use_id call id
  • content str
  • is_error bool

ModelResponse

  • assistant_message Message
  • text visible text
  • tool_uses ToolUseBlock[]

AgentStep

  • type think | call | observe | final
  • turn_index int
  • tool_* call/observe
  • decision allow | deny | ask

AgentEvent

  • type run_started...
  • run_id str
  • session_id str
  • seq int
  • payload dict

RunState

  • run_id str
  • session_id str
  • status running...
  • events AgentEvent[]
  • pending Permission?

Tool

  • name str
  • description str
  • input_schema JSON Schema
  • risk_level runtime only
  • call(input) async str

模型调用时的数据形态

发送给厂商 API 的是 messages 和 tools 两个并列字段。

{ "messages": [ {"role": "system", "content": "..."}, {"role": "user", "content": "calculate 12 * 8 + 6"} ], "tools": [ { "type": "function", "function": { "name": "calculator", "parameters": {"type": "object", "...": "..."} } } ] }

工具结果回填时的数据形态

runtime 执行工具后，把结果作为 tool_result 写回下一轮模型上下文。

Message( role="user", content=[ ToolResultBlock( tool_use_id="call_xxx", content="102", is_error=False ) ] )

ER / 状态关系图

项目没有数据库，这里是“内存 ER 图”：展示 session、run、event、permission、message、tool call 之间的关系和基数。

in-memory no database yet

Session

目前是进程内字典：SESSIONS[session_id] = messages[]。服务重启后丢失。

Run

一次用户消息对应一个 run。同一个 session 同时只允许一个 active run。

Event

SSE 推送的是 AgentEvent，不是 token。每个 session 有独立递增 seq，支持重连重放。
